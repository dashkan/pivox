# WinUI 3 + CMake Integration Guide

Reference guide for building WinUI 3 (C++/WinRT) apps with CMake. Extracted from a working reference project that ships a full WinUI 3 app with XAML, IDL, NuGet, and custom controls.

## CMake Constraints (WinUI 3 / XAML)

These are hard-won lessons — each one caused build failures that took hours to diagnose.

### 1. Directory.Build.props/targets must NOT be in project root

MSBuild walks up the directory tree from the build directory. If it finds Directory.Build.props at the project root, it breaks CMake's compiler detection during `cmake -G "Visual Studio ..."`.

**Fix:** Store them as `.in` templates in the source tree, use `configure_file()` to copy into the build directory.

```cmake
configure_file(
    "${CMAKE_SOURCE_DIR}/platform/windows/Directory.Build.props"
    "${CMAKE_BINARY_DIR}/Directory.Build.props" COPYONLY)
configure_file(
    "${CMAKE_SOURCE_DIR}/platform/windows/Directory.Build.targets"
    "${CMAKE_BINARY_DIR}/Directory.Build.targets" COPYONLY)
```

### 2. App.idl must be an empty namespace block

**NOT** a runtimeclass. Declaring App as a runtimeclass generates conflicting factory functions that prevent the app from launching.

```idl
// CORRECT
namespace Pivox {}

// WRONG — do NOT do this
namespace Pivox { runtimeclass App : ... {} }
```

### 3. App.xaml.cpp should NOT include App.g.cpp

Other windows (MainWindow, custom controls) SHOULD include their `.g.cpp`, but App should not. The App factory is handled differently.

### 4. XAML ApplicationDefinition

`App.xaml` must be tagged as the application definition:

```cmake
set_property(SOURCE platform/windows/App.xaml PROPERTY VS_XAML_TYPE "ApplicationDefinition")
```

All other `.xaml` files default to "Page" which is correct.

### 5. IDL/XAML dependency wiring

Required for `module.g.cpp` to include the correct headers. Without this, the generated code doesn't know about your XAML types and the build fails with missing symbols.

```cmake
get_target_property(SOURCES ${TARGET} SOURCES)
foreach(SOURCE ${SOURCES})
    cmake_path(GET SOURCE EXTENSION LAST_ONLY EXTENSION)
    if(NOT "${EXTENSION}" STREQUAL ".idl")
        continue()
    endif()
    set(IDL_SOURCE "${SOURCE}")
    cmake_path(REMOVE_EXTENSION SOURCE LAST_ONLY OUTPUT_VARIABLE BASENAME)
    set(XAML_SOURCE "${BASENAME}.xaml")
    if("${XAML_SOURCE}" IN_LIST SOURCES)
        set_property(SOURCE "${IDL_SOURCE}" PROPERTY VS_SETTINGS
            "SubType=Code" "DependentUpon=${XAML_SOURCE}")
    else()
        set_property(SOURCE "${IDL_SOURCE}" PROPERTY VS_SETTINGS "SubType=Code")
    endif()
endforeach()
```

### 6. Custom controls need header in pch.h

Code-only controls (no .xaml file, just .idl + .h + .cpp) must have their header included in `pch.h` so that `XamlTypeInfo.g.cpp` can find them.

### 7. #undef GetCurrentTime

Required in `pch.h` after `#include <windows.h>` to prevent Win32 macro collision with WinRT animation headers:

```cpp
#include <windows.h>
#undef GetCurrentTime  // Win32 macro collides with WinRT
```

### 8. NuGet packages

Set via `VS_PACKAGE_REFERENCES` property on the WinUI target:

```cmake
set_property(TARGET ${TARGET} PROPERTY VS_PACKAGE_REFERENCES
    "Microsoft.Windows.CppWinRT_2.0.240405.15"
    "Microsoft.WindowsAppSDK_1.7.250401001"
    "Microsoft.Windows.SDK.BuildTools_10.0.26100.1742"
)
```

### 9. WinUI 3 target properties

```cmake
set_target_properties(${TARGET} PROPERTIES
    VS_GLOBAL_RootNamespace "Pivox"
    VS_GLOBAL_AppContainerApplication "false"
    VS_GLOBAL_AppxPackage "false"
    VS_GLOBAL_CppWinRTOptimized "true"
    VS_GLOBAL_CppWinRTRootNamespaceAutoMerge "true"
    VS_GLOBAL_UseWinUI "true"
    VS_GLOBAL_ApplicationType "Windows Store"
    VS_GLOBAL_WindowsPackageType "None"
    VS_GLOBAL_EnablePreviewMsixTooling "true"
    VS_GLOBAL_WindowsAppSDKSelfContained "true"
)
```

### 10. Release PDBs for debugging

Generate debug info in Release builds so you can debug without switching to Debug config:

```cmake
target_compile_options(${TARGET} PRIVATE "$<$<CONFIG:Release>:/Zi>")
target_link_options(${TARGET} PRIVATE "$<$<CONFIG:Release>:/DEBUG>")
```

## Directory.Build.props

```xml
<Project>
  <PropertyGroup Condition="'$(ProjectName)' == 'Pivox'">
    <RuntimeIdentifiers>win10-x64;win10-arm64</RuntimeIdentifiers>
    <NuGetTargetMoniker>native,Version=v0.0</NuGetTargetMoniker>
  </PropertyGroup>
</Project>
```

The `Condition` prevents these properties from affecting other targets (like test libraries).

## Directory.Build.targets

```xml
<Project>
  <ItemGroup Condition="'$(ProjectName)' == 'Pivox'">
    <ClCompile Include="$(GeneratedFilesDir)module.g.cpp" />
  </ItemGroup>
  <ItemDefinitionGroup Condition="'$(ProjectName)' == 'Pivox'">
    <Midl><OutputDirectory /></Midl>
  </ItemDefinitionGroup>
</Project>
```

- `module.g.cpp` is auto-generated by MIDL from all `.idl` files. Must be compiled.
- Empty `OutputDirectory` is a CMake workaround — prevents MIDL from outputting to a broken path.

## Build Commands

```bash
# Windows x64
mkdir build-win-x64 && cd build-win-x64
cmake -G "Visual Studio 18 2026" -A x64 ..
cmake --build . --config Release
ctest -C Release  # run tests
```

## Testing with MSTest

WinUI 3 apps can be tested with MSTest for unit tests. The test project should be a separate CMake target that links against the shared core library and tests view model logic without requiring the XAML runtime.
